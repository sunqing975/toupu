# 领域模型

## 1. 核心实体

### InvestmentAccount（投资账户）

代表用户在某个券商、基金销售平台、银行或现金管理载体中的账户。一个账户可以持有多个标的和现金余额。同一只基金在不同平台持有时，必须按账户分别核算。

### Instrument（投资标的）

第一版类型：`FUND`、`ETF`、`STOCK`。通过 `market + exchange + code` 唯一识别。标的静态属性与供应商代码映射分开保存。

### InvestmentTransaction（投资业务事件）

表示用户发起或确认的一项业务，例如股票买入、基金申购、现金入金、分红或转账。交易状态和业务类型由领域规则控制。

### TradeExecution（成交）

仅用于交易所证券的实际成交。一个证券交易业务可以有多条成交记录。持仓数量只由已确认的成交产生。

### FundConfirmation（基金确认）

保存基金申购/赎回最终确认日期、净值、份额、确认金额和费用。申购申请与确认结果分开。

### JournalEntry / JournalLine（账务事件/分录）

表示已确认业务对资产、现金、费用和损益造成的影响。每个 JournalEntry 必须借贷平衡。

### PositionLot（持仓批次）

记录某次买入/申购形成的份额及剩余成本。卖出/赎回时记录成本分摊。批次是成本核算辅助事实，不替代交易和账本。

### CorporateAction（公司行为）

记录市场层面的分红、送股、转增、拆股等事件。账户层面的实际处理结果另行记录。

### MarketQuote / FundNav（行情/基金净值）

行情是估值输入，不是交易事实。每条数据保留来源、采集时间、市场时间和质量标记。

## 2. 交易类型

第一版建议的业务事件类型：

- `STOCK_BUY`, `STOCK_SELL`
- `ETF_BUY`, `ETF_SELL`
- `FUND_SUBSCRIBE`, `FUND_REDEEM`, `FUND_CONVERT`
- `CASH_DIVIDEND`, `DIVIDEND_REINVEST`
- `DEPOSIT`, `WITHDRAW`, `ACCOUNT_TRANSFER`
- `BONUS_SHARES`, `STOCK_SPLIT`, `OTHER_CORPORATE_ACTION`
- `FEE_ADJUSTMENT`, `OPENING_BALANCE`

业务类型比简单 BUY/SELL 更明确，可避免服务层根据标的类型猜测业务语义。也可以用 `asset_type + action` 组合，但必须保证数据库和 API 语义唯一。

## 3. 账户转账

账户转账是一项业务事件，必须产生一对关联现金分录：转出账户减少、转入账户增加。不得把转账记成收入或支出。若跨币种（第一版不支持），未来必须增加汇率和汇兑差额处理。

## 4. 初始资产

首次使用系统时，需要导入已有现金和持仓。初始资产不应伪造成历史买入交易。使用 `OPENING_BALANCE` 业务事件和对应期初科目建立起始账面余额，并记录：

- 期初日期；
- 账户；
- 标的；
- 数量；
- 账面成本；
- 期初现金；
- 成本口径及来源可信度。

若缺少历史买入批次，必须明确标记为“期初汇总批次”，不能假装掌握真实历史批次和基金持有期限。

## 5. 状态流转

交易草稿：`DRAFT -> CONFIRMED -> POSTED`。

证券委托/成交：`DRAFT -> CONFIRMED -> PARTIAL -> POSTED`；无成交取消为 `CANCELLED`。如果委托系统不在第一版实现，可以直接手工录入成交事实，不必模拟券商委托生命周期。

基金申赎：`DRAFT -> CONFIRMED -> POSTED`，其中确认数据到达之前不得增加/减少最终份额。可使用单独的 `confirmation_status` 表示待确认、已确认、失败。

已入账事件通过冲正流程处理，原状态和记录保留。

## 6. 核算口径分离

至少区分：

- 现金账面余额；
- 证券/基金持有数量；
- 证券/基金账面成本；
- 市场估值；
- 已实现损益；
- 未实现损益；
- 现金分红收入；
- 费用和税费；
- 外部资金流入/流出。

总资产 = 现金余额 + 各项持仓市场价值 + 其他纳入资产 - 负债（第一版若无负债，可为零）。收益指标不可简单使用“当前市值 - 累计买入金额”，必须明确外部资金流、分红、费用和估值时间。
