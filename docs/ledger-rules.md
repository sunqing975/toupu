# 账本与金融核算规则

> 本文档定义账务语义。代码实现不得自行改变以下规则。涉及中国市场具体费率、税率、交易单位、基金费率或交易制度时，应从可配置规则或可靠来源取得，禁止把可能变化的数字硬编码为永久常量。

## 1. 基本原则

- 业务事件记录“发生了什么”；账务分录记录“资产如何变化”。
- 只有确认且满足入账条件的业务事件才可以过账。
- 每个已过账 JournalEntry 借贷平衡。
- 过账不可逆修改；更正通过冲正和新事件完成。
- 账务币种第一版统一 CNY。
- 所有计算使用 Decimal；数据库使用 NUMERIC。

## 2. 复式记账科目

建议最小科目类型：

- `CASH`: 账户现金资产。
- `SECURITY`: 某账户某标的的账面资产成本。
- `FEE_EXPENSE`: 交易费用。
- `DIVIDEND_INCOME`: 现金分红收入。
- `REALIZED_GAIN`: 已实现收益。
- `REALIZED_LOSS`: 已实现损失。
- `OPENING_BALANCE`: 期初余额平衡科目。
- `TRANSFER_CLEARING`: 账户转账清算（如业务需要）。

借贷方向按会计惯例定义：资产增加记借方，资产减少记贷方；费用增加记借方；收入和收益增加记贷方。具体科目方向需通过科目配置和测试统一。

## 3. 股票/ETF 买入

假设买入 100 股，成交价 10 元，佣金 5 元，实际现金扣款 1005 元。若交易费用计入持仓成本：

- 借：证券资产 1005；数量 +100。
- 贷：现金 1005。

成交记录仍分别保存成交金额 1000 和佣金 5。PositionLot 成本为 1005。不要同时再借记费用，否则会重复计入成本。

如果未来支持将某些费用费用化，必须通过明确的成本政策配置，不能同一费用既资本化又费用化。

## 4. 股票/ETF 卖出

假设卖出收入扣除费用后的净额为 1195 元，被卖出持仓分摊成本为 1005 元：

- 借：现金 1195。
- 借：证券资产处置/已实现损失或相关清算科目（根据具体分录方案）。
- 贷：证券资产 1005。
- 贷：已实现收益 190。

实现时可采用“卖出净收入与出库成本差额记入 REALIZED_GAIN/LOSS”的标准模板，必须确保借贷平衡。成交费用保留在 execution 明细中，并避免重复扣减。

部分卖出必须记录每个被消耗 lot 的数量和成本分摊。第一版统一成本策略可先采用移动加权平均，但批次记录仍保留；FIFO 可作为后续可选核算视图。对 A 股税务或券商实际交割单有差异时，以真实费用记录为准。

## 5. 场外基金申购

申购申请和确认结果分开：

- 提交申请时，记录申请金额、申请日期、渠道、费率/预计费用；未确认前不增加最终持仓份额。
- 确认后记录确认日期、确认净值、确认份额、确认金额、实际费用。
- 以真实扣款金额和实际确认份额为准，不能用估算净值代替确认净值。
- 申购费用是否计入持仓成本，应按系统统一成本政策执行并单独保留费用明细，保证现金扣款、证券资产成本和费用统计不重复。

第一版建议基金持仓成本采用“实际现金流出（含申购费用）”作为成本基础；基金平台若提供确认金额和费用，按其语义拆分，必须在数据映射文档中定义字段含义。

## 6. 场外基金赎回

- 赎回申请不立即减少已确认持仓，直到确认结果到达。
- 确认后按确认份额减少持仓。
- 按基金业务规则计算/记录赎回费用。
- 赎回净到账金额、被赎回份额对应成本、已实现损益分别记录。
- 不同渠道持有同一基金时，分别核算持有份额、成本和可能不同的赎回费率。
- 若无法还原真实批次持有期限，应标记成本批次来源不完整，不能推断费率。

## 7. 分红和红利再投资

现金分红：

- 现金余额增加；
- 记录分红收入；
- 不应增加证券份额。

红利再投资：

- 记录分红权益/收入；
- 根据确认净值和实际确认份额增加持仓；
- 不应同时把同一笔分红作为现金留存。

除权除息造成的价格变化不应被错误地当成投资损失；收益分析需要将分红纳入总回报。

## 8. 送股、转增、拆股

- 数量按公司行为比例调整。
- 不产生虚构现金流。
- 原持仓总成本原则上保持不变，单位成本随数量变化。
- 记录公司行为来源、除权日、股权登记日、实际到账数量和账户处理状态。
- 零碎股、税费或特殊分配按实际记录处理，不猜测。

## 9. 账户入金、出金和转账

- 入金：现金增加，对应外部资金流入。
- 出金：现金减少，对应外部资金流出。
- 账户间转账：一个账户现金减少，另一个账户现金增加；对组合层面不是外部资金流。
- XIRR/TWR 计算时，账户间内部转账不能被当成组合外部现金流。

## 10. 初始持仓和现金

初始化时通过期初余额事件录入。初始持仓需要数量、账面成本、估值日期和数据来源。无法取得历史交易批次时建立 opening lot，并标记 `lot_origin=OPENING_BALANCE`，不得伪造历史买入日期。

## 11. 成本方法

第一阶段推荐：

- 股票/ETF：移动加权平均成本作为默认持仓核算口径。
- 场外基金：按账户/渠道分别核算；支持基金申赎确认和持有期限信息。赎回费用按实际费用或可验证的费率规则计算。
- 批次 lot 作为可追溯底层记录。后续可增加 FIFO 视图，但不得无说明切换报表口径。

卖出时：按当前移动平均单位成本计算出库成本，剩余持仓成本同步扣减。因精度产生的尾差在最后一次清仓时归零并记录舍入调整，不得静默丢弃。

## 12. 收益指标

- 已实现盈亏：卖出/赎回净收入减去出库成本。
- 未实现盈亏：当前估值减去剩余账面成本。
- 现金分红：单独统计，并在总回报指标中按定义纳入。
- XIRR：基于外部现金流日期和金额以及期末估值计算；组合内部转账不算外部流量。
- TWR：按外部现金流发生点切分子期间收益，再连乘。
- 最大回撤：基于统一频率、同一估值口径的组合净值序列计算。

在开发 XIRR/TWR 前，必须先补充公式、现金流正负号约定、估值缺失处理和测试样例。

## 13. 行情和估值质量

行情至少保存：供应商、采集时间、市场时间、数据类型、延迟标志、复权类型、质量状态。

- 基金正式净值与盘中估值分表或明确区分。
- 盘中估值不可覆盖正式净值。
- 价格过期时显示过期状态，不可静默显示为实时。
- 停牌、无报价、交易日缺失需要有明确状态。
- 历史收益计算必须明确使用前复权、后复权还是未复权价格；账本成交价格永远保存原始成交价。

## 14. 舍入与精度

- 数据库精度根据业务设置，不统一截断为两位小数。
- 计算中间值保留足够精度。
- 舍入规则按业务/数据源规范配置。
- 展示层格式化不回写数据库。
- 每种舍入策略都需要测试覆盖。

## 投顾组合整体记账补充（2026-11-14）

- 投顾组合采用独立advisory_flows不可覆盖资金子账，非单只基金，不虚构份额/净值、不创建底层申赎或position_lots。展示引用已有平台市值，不额外产生第二份资产。
- CONTRIBUTION为名义转入，个人实付=名义金额-福利抵扣；WITHDRAWAL/REFUND为实际取回/退款。按快照日期过滤流水，名义收益=平台市值+取回+退款-名义转入-外部另付费用；个人收益改减个人实付。均需提示以完整历史为前提。
- 费用INTERNAL不重复扣已含费用的市值，UNKNOWN仅证据不作扣款；EXTERNAL才计入额外个人支出。申购费用作为转入原始证据保留，不重复增加投入。未知收费来源不猜测。当前子账未并入通用journal/组合总览收益指标，禁止声称底层完整账本已重建。

## 15. M3 场外基金实现口径（第一版）

本节的字段语义与状态机是 §5–§7 的落地约定，代码不得自行改变。

### 15.1 生命周期与状态

- 申购 / 赎回 / 红利再投资是「两段式」业务：`DRAFT`（申请，`confirmation_status=PENDING`）→ 确认（`status=CONFIRMED`、`confirmation_status=CONFIRMED`，写 `fund_confirmations`）→ `POSTED`。
- **确认数据到达前不得过账、不得增减最终份额**；`post_transaction` 对这三类交易强制校验 `confirmation_status=CONFIRMED`。
- 申请失败可置 `confirmation_status=FAILED`、`status=CANCELLED`，不产生任何账务影响。
- 现金分红（`CASH_DIVIDEND`）以平台到账为既成事实，创建时即 `status=CONFIRMED`、`confirmation_status=CONFIRMED`，无需确认阶段，不写 `fund_confirmations`。
- 完整基金转换（`FUND_CONVERT`）第一版不开放。历史重建缺少原基金成本时，允许明确标记为“转换转入历史边界”的 OPENING_BALANCE 持仓注入，不伪造原基金赎回/买入，不记为账户新增入金。保留原始转换金额、退款、费用、转入份额/净值和原基金名称。边界成本按转出金额扣除实际退回资金（含已发生费用），不声称是原基金历史成本；组合生命周期收益不完整。边界日期是导入选定的起算日期，不冒充缺失的确认日期。
- 用户明确授权的历史基金导入：普通申购按确认日过账，实际申请时间及支付渠道保存在原始证据；外部银行卡/余额宝直接支付，生成等额DEPOSIT资金桥接，再申购，不虚构外部账户余额。赎回确认日期缺失时可按实际到账日作保守记账日期并注明非真实确认日期，到账后等额WITHDRAW转出统计边界，保留申请/到账时间。整批含资金桥接、确认、过账、来源与去重记录单事务；失败全部回滚。净值与份额不能推测为当前官方净值。

### 15.2 字段语义（数据映射）

| 字段 | 申购 | 赎回 | 红利再投资 | 现金分红 |
|---|---|---|---|---|
| `fund_order_details.apply_amount` | **实际扣款总额（含申购费）** | 预估金额，可空 | 预估分红金额，可空 | 现金到账金额 |
| `fund_order_details.apply_shares` | 空 | **申请赎回份额** | 预计份额，可空 | 空 |
| `fund_order_details.platform` | 渠道（渠道分别核算） | 同左 | 同左 | 同左 |
| `fund_confirmations.nav` | 确认净值 | 确认净值 | 确认净值 | 不适用 |
| `fund_confirmations.confirmed_shares` | 确认份额 | 确认份额 | 确认份额 | 不适用 |
| `fund_confirmations.confirmed_amount` | 净申购金额（= 扣款 − 申购费） | 赎回总额（= 份额 × 净值） | 分红总额（= 份额 × 净值） | 不适用 |
| `fund_confirmations.fee_amount` | 实际申购费 | 实际赎回费 | 0 | 不适用 |

确认时强制金额守恒：`申购 apply_amount == confirmed_amount + fee_amount`。净值与份额按平台回报原样保存，不反推、不用估值代替确认值。

### 15.3 分录模板（借贷平衡）

- **申购**：借 `SECURITY` = `apply_amount`（成本基础＝实际现金流出含申购费），贷 `CASH` = 同额。建立 `lot_origin=FUND` 的批次，成本 `apply_amount`，数量 `confirmed_shares`，单位成本 = 成本 / 份额，开仓日 = 确认日。不单独借记费用，避免重复计入成本。
- **赎回**：借 `CASH` = `confirmed_amount − fee_amount`（净到账），贷 `SECURITY` = 移动加权平均出库成本，差额贷 `REALIZED_GAIN` 或借 `REALIZED_LOSS`。按 `confirmed_shares` 减少持仓；全额赎回时出库成本取剩余总成本、尾差归零。
- **现金分红**：借 `CASH` = 到账金额，贷 `DIVIDEND_INCOME` = 同额。**不增加份额、不产生第二条现金流**。
- **红利再投资**：借 `SECURITY` = `confirmed_amount`，贷 `DIVIDEND_INCOME` = 同额。建立 `lot_origin=DIVIDEND_REINVEST` 的批次；**不重复把同一笔分红记作现金**。

### 15.4 成本口径与冲正

- 场外基金与股票/ETF 共用「移动加权平均」成本口径（`positions/service.py:reduce_position`），但**处理器完全分离**：基金走 `app/funds/handlers.py`，不复用证券成交明细逻辑（agent.md §3）。
- 不同渠道（不同投资账户）分别核算份额、成本与批次，不跨账户合并。
- 申购 / 红利再投资冲正：仅当其形成的批次未被消耗时允许，冲正时删除批次；已被赎回消耗则必须走反向交易。
- 赎回冲正暂不开放（需还原批次消耗轨迹），与证券卖出冲正一致。
- 现金分红无批次，可直接冲正。

## 16. M4 导入与期初资产实现口径（第一版）

本节是 §10（初始持仓和现金）与 agent.md §7（导入规范）的落地约定，代码不得自行改变；不改 §3–§15 既有语义。

### 16.1 导入状态机（八步，缺一不可）

上传 → 原始行保存 → 解析/标准化 → 校验 → 重复检测 → 预览 → 人工确认 → 正式入账。

- 上传阶段只写 `import_batches` / `import_records`，**不得写 investment_transactions / journal_* / position_lots**（agent.md §7「导入阶段不得直接写正式账本」）。
- 只有 `POST /api/v1/imports/batches/{id}/confirm` 才创建 `OPENING_BALANCE` 交易并过账，且整批在同一数据库事务内完成（原子化：任一行失败整批回滚，不留半批账务）。
- 批次状态 `DRAFT → CONFIRMED | CANCELLED`；`CONFIRMED` 后不可再次确认，重复调用返回同一结果（幂等）。`DRAFT` 可取消。
- 原始表头与原始行以 JSONB 原样保留（`import_batches.raw_headers` / `import_records.raw`），不得丢弃（agent.md §7「原始数据必须保留」）。

### 16.2 去重键（文件级 + 业务级）

- 文件级：上传时对文件字节做 SHA-256；同一模板下已存在相同 `file_hash` 的批次则直接拒绝（409「该文件已导入过」），不生成新批次。
- 业务级：每行生成 `dedup_key`，优先使用平台外部编号 `external_id`（`OB|EXT|{account_id}|{external_id}`）；否则用规范化字段组合：
  - 现金：`OB|CASH|{account_id}|{business_date}|{amount}|{currency}`
  - 持仓：`OB|POS|{account_id}|{instrument_id}|{business_date}|{quantity}|{total_cost}|{currency}`
  - 金额/数量一律先 `quantize(0.000001)` 再拼字符串，避免 `10050` 与 `10050.000000` 被当成两行。
- 校验阶段即做重复检测（同文件内 + 已 `IMPORTED` 的历史行），重复行标 `DUPLICATE` 并在预览中展示；确认阶段只过账 `VALID` 行且再次核对，绝不重复记账。
- `investment_transactions.idempotency_key = "import:" + dedup_key`，复用 0001 的唯一索引作最终兜底；`journal_entries.transaction_id` 唯一 + `post_transaction` 幂等保证同一交易不会二次入账。

### 16.3 期初分录模板（借贷平衡，§10 落地）

`OPENING_BALANCE` 是「从组合外部注入初始资产」的既成事实，**不是一笔历史买入**：不产生现金流出、不伪造成交日期、不得记为 DEPOSIT（domain-model §4「初始资产不应伪造成历史买入交易」）。

- 期初现金（`row_kind=CASH`）：借 `CASH`（账户）= 金额，贷 `OPENING_BALANCE`（外部平衡科目）= 同额。`total_amount = 金额`。
- 期初持仓（`row_kind=POSITION`）：借 `SECURITY`（账户+标的）= 账面成本总额，贷 `OPENING_BALANCE` = 同额。同时建立 `position_lots` 批次：`lot_origin=OPENING_BALANCE`、`quantity=确认数量`、`total_cost=账面成本总额`、`unit_cost=total_cost/quantity`、`open_date=business_date`（期初/估值日期），即 domain-model §4 的「期初汇总批次」。`total_amount = total_cost`。
- 单位成本由 `total_cost / quantity` 推导，不接受用户直接传入的 `unit_cost`，避免与总额矛盾。
- `cost_source`（来源可信度）与 `valuation_date`（估值日期）保留在 `opening_balance_details`；不得假装掌握真实历史买入批次或基金持有期限。

### 16.4 错误定位与校验

- 每条错误返回 `{row_no, field, message}`；`row_no` 为文件物理行号（表头第 1 行，首条数据第 2 行），可定位到具体行与字段（agent.md §7）。
- 必填缺失、金额/数量非正数、日期格式错误、账户不存在、标的（`market`+`code`）不存在、行类型非法，都必须给出可读中文原因，绝不静默跳过。
- 行状态 `VALID | ERROR | DUPLICATE | IMPORTED | SKIPPED`；`ERROR` / `DUPLICATE` 行永不入账。
- 存在 `ERROR` 行时**整批拒绝确认**（409），避免用户误以为错误行已被处理；`DUPLICATE` 行跳过，不阻止确认。至少需 1 条 `VALID` 行。

### 16.5 冲正

- `OPENING_BALANCE` 可冲正：冲正分录方向翻转；若该行建立了持仓批次且批次未被消耗，冲正时删除批次；期初现金行无批次，可直接冲正。
- 批次已被卖出/赎回消耗时拒绝冲正，须录入反向交易更正（与 §11 一致）。

### 16.6 范围边界（第一版）

- 仅支持 `OPENING_BALANCE` 模板（期初现金 + 期初持仓）；历史成交流水导入、公司行为、费用调整留待后续，本版不伪造成交明细。
- 支持 CSV 与 Excel(.xlsx)；模板与字段映射由 `import_templates` / `import_field_mappings` 定义，首次使用时惰性初始化（迁移可从空库执行）。
- Agent 不得调用导入确认接口（agent.md §8 写操作先 proposal/draft）；导入 API 不暴露给 Agent 自动调用。
- 期初余额是「起始账面余额」而非外部现金流；XIRR/TWR 按 §12 口径处理，本版不实现指标，仅保留口径说明。

## 17. M5 行情与收益实现口径（第一版）

> 依据 agent.md §6/§10、ledger-rules §12/§13、implementation-plan M5、architecture §5。
> **先定义公式与人工基准，再实现代码**；本版不接入外部 SaaS，不伪装实时行情。

### 17.1 范围与不可违反项

- 数据源走 `market_data` 模块的 Provider/Adapter 接口（`get_quote` / `get_fund_nav` / `get_daily_history`）；业务模块只依赖标准化结果，**不直接依赖第三方 SDK**（architecture §5）。第一版只提供 `MANUAL` Provider（用户/运维显式录入行情，带来源与质量标记），预留可替换接口。
- 行情是**估值输入，不是交易事实**：账本成交价永远保存原始成交价，行情不得覆盖账本（§13、architecture §4）。
- 基金正式净值与盘中估值明确区分（`data_type=OFFICIAL|ESTIMATED`）；**盘中估值不得覆盖正式净值，也不得当作正式净值用于估值**。
- 每条行情保留：供应商、供应商原始代码、采集时间、市场时间、数据类型、延迟/估值标记、复权类型、质量状态（§13、architecture §5）。
- 快照是**可删除重建的派生结果**，必须能从已过账账本事件重建；不得把快照当事实来源（agent.md §1、database-design §3）。
- **行情缺失/过期不伪装成实时**：估值接口返回 `UNKNOWN`/`STALE` 状态并列出缺失标的；收益指标在估值覆盖不全时返回 `INSUFFICIENT_DATA`，不得静默用旧值或 0 代替。

### 17.2 账本派生口径（快照/盈亏的唯一来源）

方向约定 `DEBIT=+`、`CREDIT=−`（资产/费用类）或对收入类取反；金额一律 `Decimal`，中间值不提前量化，输出按 §14 六位小数。**快照记录的是「重建时点的当前账面余额」**，用当天重建得到的实时余额加上 `snapshot_date` 标签保存；以后查询历史指标直接读已保存的快照序列，**不回放历史账本**。

- 现金账面余额 `cash(account)` = Σ 该账户 `CASH` 科目全部分录行的 `DEBIT − CREDIT`（`journal_lines` join `journal_entries`/`ledger_accounts`；冲正分录方向已翻转，故自动抵消）。
- 持仓数量 `quantity(account, instrument)` = Σ `position_lots.remaining_quantity > 0` 的 `remaining_quantity`（与 `/api/v1/positions` 同源）。
- 持仓账面成本 `book_cost(account, instrument)` = Σ 同源批次的 `total_cost`。**双口径交叉校验**：另算 `SECURITY` 科目分录行的 `DEBIT − CREDIT`；二者不一致时 `rebuild` 整批报错（不多写、不静默取其一），因为这说明批次轨迹与账本分录脱节。
- 已实现盈亏 `realized` = Σ `REALIZED_GAIN` 科目 `CREDIT` − Σ `REALIZED_LOSS` 科目 `DEBIT`（全量累计，冲正已抵消）。
- 现金分红收入 `dividend_income` = Σ `DIVIDEND_INCOME` 科目 `CREDIT`（单独统计，不并入已实现盈亏）。
- 市场价值 `market_value` = `quantity × 有效报价`；未实现盈亏 `unrealized = market_value − book_cost`。**仅对有有效报价的持仓计入**；无报价持仓单独列 `UNKNOWN`，并从 `market_value`/`unrealized` 合计中排除（同时给出覆盖率 `coverage = 已估值持仓数 / 全部持仓数`）。
- 总资产 `total_assets = Σ cash + Σ market_value(已估值)`；`OPENING_BALANCE` 期初行是起始账面余额，已通过上述科目余额体现，不重复计。

**第一版边界（不猜测）**：`position_lots` 的批次在部分卖出时会删除已清空批次、清仓时只清零不写 disposal，因此**无法从批次/处置明细可靠重建任意历史日的数量**。故 v1 的 `rebuild` 只按当前实时余额生成快照，`snapshot_date` 是保存标签而非历史回放参数；历史某日的账面余额如需精确回溯，未来须引入时序账本视图，本版明确不支持、不伪造。XIRR 的现金流来自不可变的 `investment_transactions`（含 `business_date`，天然可回溯），期末估值取当前总资产；TWR/MDD 取已保存的 `portfolio_snapshots` 序列，缺估值点即 `INSUFFICIENT_DATA`。

### 17.3 外部现金流边界（XIRR/TWR 的关键）

按 `investment_transactions.transaction_type` 判定，**账户间转账 `ACCOUNT_TRANSFER` 是组合内部转账，绝不作为外部现金流**（§9）：

| 交易类型 | 是否外部现金流 | 说明 |
|---|---|---|
| `DEPOSIT` | 是，流出投资者 | 现金流入组合 |
| `WITHDRAW` | 是，流入投资者 | 现金流出组合 |
| `OPENING_BALANCE` | **期初资本基数** | 起始账面余额，按 §17.4 作为期初投入 |
| `ACCOUNT_TRANSFER` | 否 | 内部转账，组合层面抵消 |
| 证券买卖 / 基金申赎 / 分红 / 再投资 / 费用 | 否 | 组合内部资产形态变化或投资回报，不属外部资金流 |

现金分红 `CASH_DIVIDEND` 增加组合现金、已包含在期末估值中，**不再单列为外部现金流**（避免重复计算）；红利再投资同理。

### 17.4 XIRR（含正负号约定与缺失处理）

- 采用**投资者视角**：投入组合为负、收回为正。
  `DEPOSIT` → `CF = −amount`；`WITHDRAW` → `CF = +amount`；`OPENING_BALANCE` → 在期初日按 `CF = −期初账面净值`（期初资本基数，含期初现金 + 期初持仓成本）；期末追加 `CF_T = +V_T`（`V_T` = as_of 总资产，须估值覆盖完整）。
- 方程（实际天数/365，无复利年化假设歧义）：

  ```
  NPV(r) = Σ_i CF_i / (1 + r)^((d_i − d_0)/365) = 0
  ```

  其中 `d_0` 为最早现金流日期，`d_T = as_of`，`CF_T = V_T`。
- 求解：在 `r ∈ (−0.9999, 10]` 上二分 200 次、`|NPV| < 1e-10` 收敛；若 `NPV(−0.9999)` 与 `NPV(10)` 同号（无解/多解歧义）则返回 `None` 并标注原因，不猜测。
- 现金流按日期聚合（同日多笔先合并）；**估值覆盖不全（`coverage < 1`）或缺少期初资本基数时返回 `INSUFFICIENT_DATA`**，不输出看似合理的数字。
- 人工基准（测试必须复现；日期严格取 365 天整倍数，使指数恰为整数）：
  - 基准 A：`CF_0 = −100000 @ 2026-01-01`，`V_T = +110000 @ 2027-01-01`（恰 365 天）→ `r = 0.100000`（精确，`−100000 + 110000/1.1 = 0`）。
  - 基准 B：`CF_0 = −100000 @ 2026-01-01`，`+50000 @ 2027-01-01`（第 365 天），`V_T = +66000 @ 2028-01-01`（第 730 天）→ `r = 0.100000`（`−100000 + 50000/1.1 + 66000/1.21 = 0`）。
  - 基准 C（无解）：`CF_0 = −100000`，`V_T = −5000`（期末为负、所有现金流同号）→ `NO_SOLUTION`，不强行输出数字。

### 17.5 TWR（外部现金流切分子期间）

- 按每个外部现金流发生点把区间切成子期间；`V_{i-1}` = 上一现金流后（或期初）的组合估值，`V_i^-` = 本次现金流**发生前瞬间**的组合估值，本次净外部流入 `F_i`。
- 子期间收益 `r_i = V_i^- / V_{i-1} − 1`；现金流后 `V_i = V_i^- + F_i`；连乘：

  ```
  TWR = Π_i (1 + r_i) − 1
  ```

- **输入契约（可实现的确定约定）**：`TWR` 基于已保存的 `portfolio_snapshots` 序列（按 `snapshot_date` 升序）和不可变外部现金流表计算。对每个现金流日期 `d_i`，要求存在 `snapshot_date <= d_i` 的最近快照作为 `V_i^-`（现金流前瞬间估值）；`V_0` 取序列首个快照；`as_of` 当天必须有快照作为 `V_T^-`。`F_i = −CF_i`（与 §17.4 正负号相反：外部流入为正）。流后 `V_i = V_i^- + F_i` 作为下一子期间起点。任一子期间缺估值快照、或 `V_{i-1} <= 0` → `INSUFFICIENT_DATA` 并列出缺失日期，不跳过、不插值、不猜测。
- 人工基准（纯函数 `twr(points, flows)`，points 为 `(日期, 估值)`）：
  `points = [(2026-01-01,100000), (2026-06-30,110000), (2026-12-31,143000)]`，
  `flows = [(2026-06-30, +20000)]`（外部流入 20000），`as_of=2026-12-31`。
  子期间 1：`V_1^-=110000 / V_0=100000 → r_1=0.1`，流后 `V_1=130000`；
  子期间 2：`V_T^-=143000 / V_1=130000 → r_2=0.1`；`TWR = 1.1×1.1 − 1 = 0.210000`。
  另一基准（无现金流）：`points=[(2026-01-01,100000),(2026-12-31,115000)], flows=[]` → `TWR=0.150000`。

### 17.6 最大回撤

- 基于**统一频率、同一估值口径**的组合净值序列 `V_t`（本版取已保存的 `portfolio_snapshots`，按 `snapshot_date` 升序）。
- `MDD = min_t ( V_t / max_{s<=t} V_s − 1 )`，返回非正数与谷/峰日期；序列少于 2 点 → `INSUFFICIENT_DATA`。
- 人工基准：序列 `[100, 120, 90, 150, 120]` → 运行峰值 `[100,120,120,150,150]`，逐点回撤 `[0,0,−0.25,0,−0.2]` → `MDD = −0.250000`（峰 120 → 谷 90）。

### 17.7 快照生成（幂等、可重建）

- `POST /api/v1/snapshots/rebuild?snapshot_date=YYYY-MM-DD` 按 §17.2 派生当日 `position_snapshots`（逐账户×品种：数量/账面成本/报价/市值/未实现/报价状态）与一条 `portfolio_snapshots`（现金/市值/总资产/累计已实现/累计分红/覆盖率/数据质量）。
- 同一日期重复 rebuild **先删后建、结果幂等**（快照不是事实，可删除重建，database-design §3）；生成不写账本、不改交易/批次。
- 报价选取：优先 `OFFICIAL` 且 `quality_status=FRESH` 且 `quote_date<=as_of` 的最新一条；`ESTIMATED` 仅作展示、不用于估值；超过 `stale_days`（默认 7）标记 `STALE`；无报价 → `UNKNOWN`。
- 复权类型本版只接受 `NONE`（账本成交价保持原始价，历史收益口径明确为未复权，§13）；如将来引入前/后复权必须先补文档与基准。
