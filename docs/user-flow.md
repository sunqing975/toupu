# 用户流程 user-flow · 投谱 Toupu

> 页面级与业务级流程定义。状态机语义以 docs/domain-model.md §5 为准。

## 1. 全局导航

```
侧边栏：
├─ 总览 (/)            ← 默认落地页
├─ 持仓 (/positions)
├─ 交易 (/transactions)
├─ 账本 (/ledger)      ← 分录流水，只读
├─ 导入 (/imports)
├─ 账户 (/accounts)
├─ 标的 (/instruments)
└─ 设置 (/settings)
```

M5/M6 后增加：分析 (/analytics)、风险 (/risk)、计划 (/plans)。

## 2. 首次使用（初始化向导）

```
打开系统 → 总览显示空态引导
  ① 创建账户（券商/基金平台，可多个）
  ② 创建标的（股票/ETF/基金，或从导入带入）
  ③ 录入期初资产：
     - 期初现金 → OPENING_BALANCE 交易 → 过账
     - 期初持仓 → OPENING_BALANCE + opening lot（不伪造历史成交）
  ④ 完成进入总览
```

规则：允许跳过③直接使用，但总览会持续提示"存在未导入期初资产"。

## 3. 手动录入流程

### 3.1 现金业务（入金/出金/转账）

```
交易 → 新建 → 选类型（入金/出金/转账）
  填账户、金额、日期 → 保存草稿
  → 草稿列表点【确认】→ 状态 CONFIRMED
  → 点【过账】→ 生成平衡分录 → POSTED
总览现金余额即时变化
```

### 3.2 股票/ETF 买卖（M2）

```
新建 → 选类型（买入/卖出）+ 标的
  录成交明细（可多笔：数量/价格/费用）
  → 保存草稿（可编辑）
  → 确认 → 过账：
    借贷平衡校验通过 → POSTED，持仓批次更新
    不平衡 → 拒绝并显示差额
```

### 3.3 场外基金申赎（M3）

```
新建申购/赎回申请（草稿）→ 确认（状态 CONFIRMED，等待确认数据）
  → 录入确认结果（净值/份额/金额/费用）→ 过账
关键：确认数据到达前，最终份额不变
```

### 3.4 冲正（任何已过账交易）

```
交易详情 → 【冲正】→ 弹窗显示将生成的反向分录
  → 确认 → 生成冲正交易 + 反向分录，原交易状态 → REVERSED
原记录保留，页面可从冲正交易跳回原交易（和反向）
```

## 4. 导入流程（M4）

```
导入 → 上传文件（自动算哈希，秒级重复检测）
  → 选择模板/字段映射
  → 解析预览：逐行校验，错误标行号+字段+原因
  → 人工勾选确认行 → 确认导入
  → 按事务批量入账（幂等，可重试）
导入全程不直接写正式账本，确认是唯一入口。
```

## 5. 风险事件处理流（M6）

```
风险扫描（定时/触发）→ 生成风险事件 → 通知（带冷却）
  → 用户在 /risk 查看 → 处理方式：
     记录处理（知悉/调整计划）或 忽略（留痕）
风险规则在 /settings/risk-rules 维护，修改留审计。
```

## 6. Agent 提案流（M6）

```
Agent（只读查询/研究）→ 生成待审批提案（operation_proposals）
  → 用户在 /plans/Proposals 审批：
     - 展示：资产、账户、数量、价格/净值、费用、金额、影响
     - 批准 → 重新校验数据后生成交易草稿（不是直接入账）
     - 拒绝 → 留痕
Agent 无任何直接写账本的工具；审批过期提案需重新校验。
```

## 7. 异常与回退路径

| 场景 | 行为 |
|---|---|
| 过账时借贷不平衡 | 阻止，显示借/贷合计与差额 |
| 重复提交同一笔录入 | 幂等键拦截，提示"该交易已存在" |
| 过账后发现录入错误 | 冲正 → 重新录入，禁止原地修改 |
| 行情/净值缺失 | 页面显示"未知/过期"，禁止用旧值冒充 |
| 导入校验失败行 | 保留原始行，用户可修正后重新确认 |
