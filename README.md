# 投谱 Toupu

个人投资记录与资产管理工具，支持人民币场外公募基金、场内 ETF 和 A 股。你在支付宝或券商完成实际交易，投谱负责记录、核算与展示，**不会代你买卖或自动下单**。

> 当前以单用户、本机使用为目标。不要直接暴露到公网；模型密钥、MCP 配置和备份均需妥善保管。

## 日常使用

- **总览**：查看已录资产、收益、持仓明细和资产分布环形图，支持按持仓或账户查看分布；展开查看份额与成本。
- **交易记录**：场内和场外共用一张列表，支持账户、品种、市场和状态筛选。新建时在表单内选择市场，不需要维护入金、出金等后台记账细节。
- **行情**：获取已公布基金净值，查看价格日期、普通持仓估值与报价覆盖；手工行情录入及快照重建目前仍作为维护功能保留。
- **助手**：配置不同 Agent，通过流式会话查询数据或辅助程序操作。
- **设置**：管理模型、技能目录、MCP、完整数据备份与恢复；后台账务明细收在“高级 · 数据核对”。

导入、账本和独立持仓不再占用日常侧栏；底层数据与兼容接口保留。

## 当前能力与边界

### 投资记录与核算

- 场内股票／ETF 保存实际成交数量、价格和费用；场外基金保存申请、确认日期、份额、净值和费用，使用不同业务处理器。
- 日常交易列表展示“已完成”和“确认份额中”。取消、失败、冲正等历史仍在后台留存，不作为日常有效交易展示。
- 复式账本作为核算基础，入账检查借贷平衡，持仓按移动加权平均成本核算；普通已入账更正遵循冲正规则。
- 支持现金分红、红利再投资、历史基金记录重建、期初资产 CSV／Excel 预览确认导入，以及确定性风险规则。
- **完整基金转换尚未实现**；历史资料不完整时只能明确记录转换转入边界，不能伪造来源基金的成本与收益。
- 投顾组合可按整体资金流水及平台金额独立记录，无需底层基金交易或虚构份额，不与底层持仓重复计算。

### 行情与收益

- 已接入公开的已公布基金净值，通过行情页“同步持仓基金净值”按钮更新现有基金；保留实际净值日期与来源，QDII 可能晚于国内基金公布。
- 已有沪深股票／ETF 日线导入 API，需要明确交易所与代码；不是实时行情系统。
- **后台定时同步尚未实现**，当前需要显式同步；投顾组合金额仍按平台资料更新。
- 总览顶部的平台收益与截图金额、按净值计算的持仓估值属于不同口径，页面会注明日期和来源。不同来源日期不能理解为同一时点的实时净资产。
- 待确认资金不增加确认份额；当前平台待确认记录与后续交易确认的自动对账仍待完善。
- XIRR、TWR、回撤依赖完整现金流和历史估值覆盖；数据不足时返回状态，不编造收益率。

### Agent、技能与 MCP

- 内置 Toupu 助手定位为**程序操作助手**，不是投资分析师；自定义 Agent 可分别挂载业务工具、指令技能目录和外部 MCP。
- 技能是包含 SKILL.md 的目录包，支持 ZIP 导入及附件读取；不会自动执行上传脚本。
- 会话采用流式接口，展示实际返回的思考与工具调用；服务端任务及事件持久化，支持断线重放和取消请求。
- 外部 MCP 支持粘贴 JSON 配置，按 Agent 绑定范围访问；外部工具调用由用户确认。本地建议不等于账户交易。
- 不自动下单，不允许模型直接确认或过账投资交易。后台任务当前为单进程实现，重启中断的任务不会自动重试潜在副作用。

## 完整数据备份与恢复

在 **设置 → 备份与恢复** 中下载完整备份，上传后先预览表及记录行数，再选择：

| 方式 | 行为 |
|---|---|
| 清空导入 | 用备份替换当前数据，保留并校验数据库迁移版本 |
| 覆盖导入 | 同主键覆盖，不同主键新增；备份里没有的现有记录保留 |
| 增量导入 | 同主键跳过，仅新增不存在的记录 |

- 按实际主键处理，包含联合主键；多数业务表使用随机 UUID，但 UUID 去重不等于业务去重。不同 ID 触发业务唯一键冲突时整批拒绝，不擅自合并。
- 恢复需要相同迁移版本、表列及类型；最大上传 50MB，不支持跨版本自动迁移。
- 必须输入“确认恢复”；执行前自动保留服务器本地安全副本，失败整批回滚，并检查账务平衡。活动助手任务需要先结束。
- **文件包含全部数据库数据，包括明文模型密钥、MCP 配置与会话，当前未加密。不要提交到 Git、公开分享或交给不可信第三方。**
- 当前文件扩展名为 .sql，但内容是投谱专用 SQL 注释封装数据，**不是可直接使用 psql 执行的 SQL 脚本**。通过投谱界面恢复；暂不支持 Excel 全库备份。
- 这是数据备份，不包含数据库建库脚本、应用代码、外部录屏或本地附件；恢复到新环境时先部署相同版本并执行迁移。恢复前副本存于服务运行用户的 ~/.toupu-backups/before-restore/ 目录，容器部署需考虑持久化。

## 技术栈

- Python 3.12+、FastAPI、Pydantic、SQLAlchemy 2.x、Alembic
- PostgreSQL 18（本地 Compose 配置）
- React、TypeScript、Vite
- pytest、ruff、mypy；前端 Node 测试与 TypeScript 构建检查
- OpenAI 兼容模型接口、MCP、目录式技能；不依赖外部 Agent 宿主才能运行

金额与数量由 Python Decimal／PostgreSQL NUMERIC 核算。页面按类型格式化金额、净值及份额，不降低后台存储精度。

## 开发快速开始

需要 Docker、uv、Node.js 和 npm。开发时只把数据库放进容器，前后端分别在终端运行。

### 1. 数据库

```bash
docker compose up -d db
```

PostgreSQL 宿主机端口为 5433，容器内为 5432。示例凭据仅用于本地开发，请勿用于公网部署。

### 2. 后端

```bash
cd backend
uv sync
# 首次配置时复制；已有 .env 不要覆盖
cp ../.env.example .env
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

配置数据库连接后，启动自动执行 Alembic 迁移。API：<http://127.0.0.1:8000>；接口文档：<http://127.0.0.1:8000/docs>。

### 3. 前端（另开终端，从仓库根目录开始）

```bash
cd frontend
npm ci
npm run dev -- --host 127.0.0.1
```

前端：<http://127.0.0.1:5180>，开发服务器将 /api 转发到后端 8000。

### 测试与检查

```bash
# 仓库根目录
cd backend
uv run pytest -q
uv run ruff check app tests
uv run mypy app

# 另一个终端，从仓库根目录开始
cd frontend
npm test
npm run build
```

后端测试由隔离夹具在导入应用前切换到独立的 toupu_test 数据库，不得使用真实投资数据库执行破坏性测试。自定义 TEST_DATABASE_URL 必须与开发库不同且以 _test 结尾；首次自动创建测试库需数据库用户有相应权限。

### 完整容器模式

```bash
docker compose --profile full up -d --build
```

Compose 前端端口为 <http://localhost:5173>，API 为 <http://localhost:8000>。它与本地开发端口 5180 不同；本地开发服务与容器 API 不要同时占用 8000。
